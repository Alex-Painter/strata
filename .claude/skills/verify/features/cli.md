# CLI

`strata` is the terminal entry point. `strata stacks <owner/repo>` lists a repo's stacks, and `strata analyze [input]` finds the stack around a PR or branch (or takes a commit range), prints it in brief, then writes the review page and the full report as JSON to Strata's data folder. With no input it takes the branch checked out in `--repo-path` or the current folder. It never writes inside a git checkout. Both commands read GitHub with `GITHUB_TOKEN`, and without one they stop before writing anything. `apps/cli/scripts/stack-vs-range.ts` is the shape-invariance check on a real stack.

## Sub-features

- `cli-help`: `--help`, `-h` or no arguments print the usage text and exit 0.
- `cli-usage-errors`: an unknown command, a missing `stacks` repo, extra arguments or an unknown option print a message, then the usage text, and exit 2.
- `cli-input-validation`: input that isn't a PR, stack, URL or range prints the accepted forms and exits 1.
- `cli-needs-token`: `analyze` and `stacks` without `GITHUB_TOKEN` say so and exit 1, writing nothing.
- `cli-stacks`: `strata stacks <owner/repo>` prints each stack as a tree, bottom PR first, with link states and issues. `--json <file>` also writes `{repo, stacks}`.
- `cli-analyze`: `strata analyze <input>` prints the path, one line per PR (how Strata built its diff, files, lines, title, and GitHub's reason when its diff differs, then Claude's sentences about it), the whole stack's `Summary` and Claude's `Guide` when the repo allows Claude (each sentence ends with the hunks it rests on, as `[path:line]`), the whole-stack files by layer (with `(inspect)` on the layers to inspect, `(inspect: <rule>: <the word> in <the name>)` on a file whose path has an inspect word, in any layer but Tests and Docs and not mechanical, and the reason a file is mechanical; a list past 40 files is cut, but never a flagged file), the `Layers by PR` matrix (`↻N` lines changed again later, `+Nm` mechanical), issues and notes. `--leaf <n>` picks a fork's path; `--repo-path` lends a checkout's objects. A range (`owner/repo@base...head`) prints its commits and `Whole diff:` instead of PRs and the matrix.
- `cli-page`: `analyze` ends with `Wrote <page>.html` and `Wrote <page>.json` on stderr: `reports/<owner>/<name>/<change id>.{html,json}` in the data folder, or `--out` (with the JSON next to it) and `--json`. The page is the web app's static build with the report embedded, and shows what the workspace shows for the same stack.
- `cli-no-checkout`: any `--out`, `--json` or data folder inside a git checkout is refused before the analysis: `Strata won't write to <path>: it's inside the git checkout <dir>, where it could be committed by accident. Choose a path outside it.`, exit 1, nothing written. `stacks --json` too.
- `cli-current-branch`: `analyze` with no input prints `… The stack around <owner/repo>:<branch>, the branch checked out in <dir>` and analyses that.
- `stack-vs-range`: the script prints `Stack: …`, `Range: …`, any of the stack's notes as `Note: …`, and `Same: the canonical reports are equal.` (exit 0), or `Different: …` and the places they differ (exit 1). When some PRs couldn't be put on the stack, it compares only those in the whole-stack diff and prints, for example, `Same, but only for #1 → #2: #3 isn't in the whole-stack diff.` (exit 1).

## How to get to it (user POV)

- From the repo: `pnpm --filter @strata/cli start <args>`. The README documents `pnpm --filter @strata/cli start --help`, and the script as `pnpm --filter @strata/cli exec tsx scripts/stack-vs-range.ts <input>`.
- `strata-verify cli <run> <name> <args>` runs the same entry, `apps/cli/src/main.ts`, through tsx with a clean environment and a throwaway `HOME` (`<run dir>/cli-data`). For a run started with `--github fixture` it also passes the fixture GitHub's URL and git remote with a dummy `GITHUB_TOKEN`, and with `--claude fixture` the stand-in Claude and a settings file turning on `sendCodeToAnthropic` for `acme/app`. Use this for proof.

## Driving it with strata-verify

Preconditions:

- Any run from `strata-verify up` (`$R`) for help, usage and validation. The CLI doesn't talk to the server.
- A run **without** `--github fixture` for the no-token checks (`$N`).
- `strata-verify up --github fixture --claude fixture` (`$R`) for `analyze`, the page and the script. `$REPO` below is the repo root (`git rev-parse --show-toplevel`). The page needs the web app's static build: `pnpm --filter @strata/web build` after any web change.

Steps:

- **Help.** `strata-verify cli $R cli/help --help` exits `0` with stdout starting `Usage: strata analyze [input] [options]`, then `strata stacks <owner/repo> [options]`, and listing `--repo-path`, `--leaf`, `--source`, `--out`, `--json`, `--data-dir` and `-h, --help`. `strata-verify cli $R cli/no-args` gives the same output.
- **Unknown command.** `strata-verify cli $R cli/unknown frobnicate` exits `2`. Stderr starts `Unknown command "frobnicate".` and is followed by the usage text.
- **Extra arguments.** `strata-verify cli $R cli/extra analyze 'owner/repo#1' extra` exits `2` with `Unexpected arguments: extra`.
- **Unknown option.** `strata-verify cli $R cli/bad-option analyze 'owner/repo#1' --bogus` exits `2` with stderr starting `Unknown option '--bogus'.`.
- **Bad input.** `strata-verify cli $R cli/bad-input analyze not-a-thing` exits `1` with `Can't read "not-a-thing". Use owner/repo#123, a PR URL, owner/repo:branch, owner/repo#12,13,14, owner/repo@base...head, or base...head inside a local checkout.`
- **No token.** `strata-verify cli $N cli/analyze-no-token analyze 'owner/repo#1'` exits `1` with stderr ending `Strata must have a GitHub token (GITHUB_TOKEN) to find stacks.` `strata-verify cli $N cli/stacks-no-token stacks owner/repo` does the same. Side effect: `strata-verify capture $N cli/no-output -- find /tmp/strata-verify/runs/$N/cli-data -name '*.html'` lists nothing.
- **Stacks usage.** `strata-verify cli $R cli/stacks-missing stacks` exits `2` with `stacks needs an <owner/repo>.`; `stacks owner/repo --out x` exits `2` with `stacks takes no --source, --out or --leaf.`
- **Leaf.** `strata-verify cli $R cli/leaf-bad analyze 'owner/repo#1' --leaf x` exits `2` with `--leaf needs a PR number, got "x".`; `analyze 'owner/repo@main...b' --leaf 3` exits `1` with `--leaf needs a PR or branch input.`
- **Analyze and the page.** `strata-verify cli $R cli/analyze-9 analyze 'acme/app#9'` exits `0`. Stdout starts `acme/app: Cache forecasts per account`, then `#9 → #10 → #11 on main, from dd4a224`, has `Summary` and `Guide`, and ends with the matrix. Stderr ends with two `Wrote` lines under `/tmp/strata-verify/runs/$R/cli-data/.strata/reports/acme/app/`. Open the `.html` in a browser (file URL), and the same stack in the web app (`stacks.md`, "Open a Change"): the text of `main` and of `complementary "Change"` should be the same in both, for the whole stack, after opening the first summary sentence, and after `button "Show #10 …"`. Check both themes and that the page has no errors.
- **Inspect flags.** The fixture has a branch with no PR, `inspect-demo`, whose files have inspect words. `strata-verify cli $R cli/analyze-inspect analyze 'acme/app@main...inspect-demo'` prints `Whole diff: 4 files, +8 -0`, then under `Data model (inspect)` the line `A migrations/0043_archive_sessions.sql  +1 -0  (inspect: Access and permissions: a word starting "session" in 0043_archive_sessions.sql; Deletion and retention: a word starting "archiv" in 0043_archive_sessions.sql)`, and under `Logic` `A app/auth/permissions.py  +2 -0  (inspect: Access and permissions: a word starting "permission" in permissions.py)  (Claude: The fixture Claude calls every file logic)`. `tests/test_permissions.py` and `docs/retention.md` have inspect words too, but carry nothing: Tests and Docs aren't flagged. On its page, choose the sidebar's `Data model` button: the `migrations/0043_archive_sessions.sql` row has the tags `Access and permissions` and `Deletion and retention`, each with its reason as a tooltip, and the facts line under it ends `Inspect: Access and permissions: a word starting "session" in 0043_archive_sessions.sql · Inspect: Deletion and retention: a word starting "archiv" in 0043_archive_sessions.sql`. In `Logic`, the `app/auth/permissions.py` row has the `Access and permissions` tag; the rows in `Tests` and `Docs` have none. `acme/app#9` has no `(inspect:` anywhere.
- **A range.** `strata-verify cli $R cli/analyze-range analyze 'acme/app@dd4a224...d59d3ed'` (the #9 stack's base and Strata's last commit, from `Range:` below) prints `Whole diff: 6 files, +32 -0` with no PR lines. Its page shows `From dd4a224, where it branched, to d59d3ed`, the Summary (`Claude wrote this from the range's diff only.`), the Guide and the files, and no stack map.
- **No checkout writes.** `strata-verify cli $R cli/out-in-repo analyze 'acme/app#3' --out $REPO/page.html` exits `1` with `Strata won't write to $REPO/page.html: it's inside the git checkout $REPO, …`, and `git -C $REPO status --short` shows no `page.html`. The same for `--json $REPO/r.json`, `--data-dir $REPO/.strata` and `stacks acme/app --json $REPO/s.json`.
- **Current branch.** Make a checkout of the fixture: `strata-verify capture $R cli/checkout -- sh -c 'git clone -q "$(cat /tmp/strata-verify/runs/'$R'/instance/remote)" /tmp/strata-verify/runs/'$R'/checkout && git -C /tmp/strata-verify/runs/'$R'/checkout remote set-url origin git@github.com:acme/app.git && git -C /tmp/strata-verify/runs/'$R'/checkout switch -q b3'`. Then `strata-verify cli $R cli/current-branch analyze --repo-path /tmp/strata-verify/runs/$R/checkout` prints `… The stack around acme/app:b3, the branch checked out in …` and the #1 → #2 → #3 stack. The checkout's `git status --short` stays empty.
- **Stack vs range.** Run the script against the fixture with the same environment `cli` uses: `strata-verify capture $R cli/stack-vs-range -- env -i PATH="$PATH" HOME=/tmp/strata-verify/runs/$R/cli-data GITHUB_TOKEN=verify-fixture-token DEV_GITHUB_GRAPHQL_URL="$(cat /tmp/strata-verify/runs/$R/instance/graphql)" DEV_GIT_REMOTE="$(cat /tmp/strata-verify/runs/$R/instance/remote)" $REPO/node_modules/.bin/tsx $REPO/apps/cli/scripts/stack-vs-range.ts 'acme/app#9'`. It prints `Range: acme/app@dd4a224...d59d3ed, 6 files, ending at Strata's last commit, since some PRs were replayed` and `Same: …`, exit 0. `#3` ends `at #3's head`. Every fixture PR should say `Same`.
- **Stacks on a real repo.** Only on the developer's Mac, where `gh` is signed in: `GITHUB_TOKEN="$(gh auth token)" pnpm --filter @strata/cli start stacks GlyphicAI/maverick-backend --repo-path ~/workspace/maverick-backend --data-dir <run dir>/cli-data`. Compare the trees with the hand-written proving stacks. `strata-verify cli` runs under `env -i`, so it can't pass the token; run this one directly and save the output with `strata-verify note`.
- **Analyze on a real repo.** Same machine and token: `GITHUB_TOKEN="$(gh auth token)" pnpm --filter @strata/cli start analyze 'GlyphicAI/maverick-backend#<tip>' --repo-path ~/workspace/maverick-backend --data-dir <run dir>/cli-data`. For each PR whose part is `direct`, merged ones included, its files should match `gh pr diff <n> --name-only`; where they don't, the line under it gives GitHub's reason. Then the script on the same stack should say `Same`. Keep the output and the page on the Mac: they name work files.

## Gotchas

- Quote `owner/repo#1`. An unquoted `#` starts a comment in zsh and bash, and the CLI then sees just `owner/repo`.
- Run it from zsh with a variable holding several words, and they reach the CLI as one argument. That produces misleading errors like `Unknown command "analyze owner/repo#1"`. Pass each argument separately.
- `pnpm --filter @strata/cli start` adds pnpm's own banner lines to stdout, and runs the CLI in `apps/cli`; the CLI resolves paths and finds the current branch from `INIT_CWD`, the folder pnpm was started in. Assert on the CLI's text, not on the first line.
- `strata-verify cli` runs in the caller's folder with no `INIT_CWD`, so `analyze` with no input there reads whatever checkout you're in. Pass `--repo-path`.
- `analyze` and `stacks` clone into the data folder (default `~/.strata`, which `strata-verify cli` puts under the run dir). Run directly, always pass `--data-dir` inside the run dir so verification never writes into the real home.
- A page from before a web change is stale until the web app is rebuilt and `analyze` runs again.
